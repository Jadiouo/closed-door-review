# 閉門會議式審查（Closed-Door Review）

把一份或一組文件交給一桌背景不同的模擬委員：每人獨立審、獨立打分，然後關起門來真的吵，最後留下共識、未解決的爭議，以及可以直接照著改的作業單。

這個方法的價值來自三件事：**觀點真的不同、衝突真的發生、結論真的能執行**。少了任何一件，它就只是把同一個意見換二十種語氣重複。

## 先講清楚的一件事

在輸出的最開頭用一兩句話說明：這是**模擬**的審查觀點，不是真的聯絡了專家，也不是彼此獨立的評分；分數代表材料的說服力，**不代表錄取率、通過率或任何真實結果的預測**。不要省略，也不要每一節重複。

## 開始前：收集四樣東西

缺的直接問使用者，一次問完，不要邊審邊問。使用者不在場（排程或無人值守）時，寫下你採用的假設後繼續。

1. **審查對象**：哪些文件、給誰看、對方大概花多久看（例如「教授每份 5–10 分鐘」）。
2. **已經定案、不再討論的決定**：使用者明講不動的事。這些只檢查「有沒有寫錯」，不重開討論。委員若強烈反對，放到辯論裡，不直接改掉。
3. **已確認的事實清單**：使用者本人確認過的經歷、數字、日期。
4. **硬限制**：字數、頁數、格式、截止日、語言。

動手前**先把使用者給的原始檔案另存一份**，再慢慢讀。長文件一定要整份讀完，不可只讀開頭就下結論。

## 絕對規則

- **不捏造**任何事實、數字、經歷或引文。建議需要補資料時，問使用者。
- **沒看過的事實不等於捏造。** 文件裡出現你在先前資料沒看過的事實時，把它列進「需要本人確認的事實」去問，**不可以判定為捏造或扣分**。只有與已確認事實**互相矛盾**時才列為疑點。
- 定案的決定不重開；已封版、已核可的文件只做事實核對，不提修改建議。
- 改寫建議**優先替換，不淨增篇幅**；有上限的文件，建議增加內容時同時說明刪哪裡。
- 嚴格、具體，不客套。稱讚要指出是哪一段、好在哪裡；不寫空泛的鼓勵。
- 清楚區分**必改**（影響讀者理解、事實、方法或對照的句子，以及實際的斷句錯誤）與**提分／選改**（能更好，但不採用也不算硬傷）。**上一輪沒採用的選改，下一輪不可重新包裝成未處理的硬傷。**
- 沿用使用者的寫作風格規則（用詞、標點、語氣、白話程度）。使用者刻意寫白話時，不要改回術語；若白話改變了技術意思，指出來並給一句同樣白話的修正。
- 改寫用文件原本的語言；英文改寫要像母語者寫的，不要中文直翻。

## 委員怎麼選

預設十位；使用者指定人數就照做（常見是十或二十）。複審時**保留上一輪全部委員**，可以加人，不換人，分數才能比較。

組成原則：

- **領域要真的不同**，依文件內容挑。研究計畫類的例子：控制理論、多智能體強化學習、機器人系統、SLAM／定位、接觸力學、模擬到真機、資料表示學習、通訊與資訊理論、人機互動。
- 一定要有幾位**不是該領域專家的角色**，他們常抓到專家看不到的問題：寫作與論證、懷疑派統計學者、計量與評估效度、可重現性把關者、產業界、教基礎課的老師、剛畢業的博士後、負責整體判斷的召集委員。
- 文件有外語版本時，加一位該語言的審查者。
- 每位委員先用**一句話**介紹背景與審查偏好（他最在意什麼、最容易為什麼扣分）。偏好要夠具體，才會產生真的分歧。

## 輸出結構

### 第一部分：逐份回饋

每份文件依序寫：

1. **有效內容**：具體哪一段好、好在哪裡。
2. **問題與改寫**：`引用原句 → 問題 → 改寫後的句子`。必改項標 **【必改】**。
3. **事實與邏輯**：前後矛盾、數字不一致、說得太滿、沒有根據的斷言（對照已確認事實）。
4. **與目標讀者的契合**：接得好不好，有沒有硬湊。
5. **限制**：字數頁數有沒有超過。
6. **範圍與語氣**：承諾做不做得完；有沒有太保守像免責聲明，或說得太滿。
7. **定案決定有沒有落實、有沒有寫錯**。
8. （複審）**上一輪必改是否真的解決，套用後有沒有產生新矛盾或斷句**。
9. **結論**：可封版／小修後封版／仍需修改。

多份文件時，先放一張**字數核對與封版總表**；再把**跨文件的共同問題**集中說一次，不要在每一份裡重複。

### 第二部分：閉門會議

1. **評分表**：每位委員 0–100 分＋一句扣分主因。複審標成「上一版 → 這一版」，並各補一句「哪裡變好、哪裡還沒解決」。評分面向預設四項，可依文件調整：
   - 高度：問題夠不夠根本，還是只換了平台或包裝
   - 連結：過去經歷能不能讓人相信「這個人做得出來」
   - 一致：同一個人在不同文件講的故事有沒有互相打架
   - 可行：時間內做得完嗎，哪一步最可能失敗
2. **自由討論**：不限題目，讓委員自己提出最在意的問題。規則：
   - 盡量讓每位委員都有機會發問、被反問
   - **至少五次明確的意見衝突**（十位以下可三次），要真的反駁、追問，不可以全部互相附和
   - 可以有人被說服而改變立場，要寫出是被哪個論點說服
   - 吵不出結果的，標明**未解決**，不要硬湊共識
   - 每場討論給一個標題和一句結論
3. **共識**：送出前最該優先處理的五件事，每件附具體改法。
4. **仍有爭議與需要本人決定的事**：分成「需要確認的事實」「需要選擇的方向」「研究或執行後才會知道的事」。第三類明說：這不是送出前必須回答的。

**分數紀律**：只修文字、沒有新增成果時，分數只能小幅移動；不要因為是最後一輪就全體加分。沒拿滿的分數，要說明哪些是文字還能修的、哪些只能靠面談或實際成果證明。

### 第三部分：個人特質（審查對象是「人」的申請文件時才寫）

材料能不能凸顯這個人的特質；哪些經歷被寫弱了、哪些可以拿掉、哪些該往前放；讀完後委員會用哪三個詞形容他，和他想被記住的樣子是否一致；複審時說明與上一輪的差別。

### 第四部分：逐句修改作業單

只列真的要改的地方；判定可封版的文件不列。每一項：

```
### 代號｜必改／提分／選改｜一句話說明
原文定位：哪份文件、哪一段
原文（精確替換範圍）：
    （原文逐字，必須在該文件中唯一命中）
問題與處理：為什麼改、這樣改解決什麼
完整替換文字：
    （可直接貼上的句子；整句刪除時明寫「刪除，無替換文字」）
篇幅：原 N 字 → 新 M 字；淨差 ±K
對應委員：哪幾位提出
```

結尾附：

- **修改後字數表**：每份文件「現況／只套必改／全部套用」三欄，對照限制。
- **封版檢查表**：內容與定案決定一致、已確認成果沒被改寫、套用與版面三類勾選項。
- **停止條件**：一句話說明做到什麼就可以停（例如「完成必改、沒有另加未確認事實、完成實際版面檢查」）。

送出前自己機械檢查一次：每段「原文」在對應文件中**恰好出現一次**、替換範圍互不重疊、套用後字數沒有超限。不預先替下一版打分。

## 最後一輪（封版判定）

使用者說「最後檢查」「最後一輪」時改用精簡模式，不再找可以更好的地方：

1. 逐項核對上一輪作業單有沒有套對
2. 只找三類新問題：套用後的斷句與銜接、跨文件矛盾、事實錯誤
3. 每份文件一行結論
4. 最後一行明確寫：**「可以繼續下一步」**，或 **「改完以下 N 項後可以繼續」**並附精確替換

封版後若使用者還想聽委員的話，給每位委員的最終分數與**一句最後建議**；建議指向口頭表達、準備方向與之後的做事方式，不再是改稿清單。

## Claude 審自己寫的東西時

這個方法也可以用來審 Claude 自己剛寫或剛改的稿。額外要求：好的、不好的都講；主動找自己加進去的套話、重複句型、前後矛盾與說得太滿的地方；不替自己的寫法辯護。

## 給其他模型用的提示詞

使用者想把同一套審查交給另一個模型時，產出一份可直接貼上的說明，依序包含：已定案的決定、會影響判斷的限制、已確認的事實（附上「沒看過的事實請問我，不要判定為捏造」）、這一版相對上一版改了什麼、審查要求（照上面的輸出結構）、規則。並提醒使用者請對方把完整回覆存成一個檔案帶回來。

## 存檔

- 使用者的原始輸入、每一輪的完整審查、作業單，各自存檔並標明輪次與日期。
- 有專案或共用空間時，存到使用者指定的位置，之後複審與面談準備都會用到。
- 對話很長時，先把使用者這一輪的指令原文另存，再開始工作。
